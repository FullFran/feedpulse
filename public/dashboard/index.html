FeedPulse

Operator console for the FeedPulse API. Register RSS feeds, match new entries against keyword rules, and deliver the resulting alerts over webhook, email or Telegram.

Access

The dashboard is served from the API origin and calls it with a tenant API key, sent as both Authorization: Bearer <key> and x-api-key. Create a key with npm run apikey:create. The key is held in this tab's sessionStorage only, so it is gone when the tab closes. When the API runs with ENABLE_AUTH=false — the default, and what a fresh docker compose up gives you — any placeholder value is accepted and every request resolves to the shared legacy tenant.

Auth mode: manual API key.

Add a rule

Keywords are comma-separated and matched as whole phrases against the entry title and content, case-insensitively and ignoring accents. Any include keyword matching is enough; any exclude keyword blocks the alert. Up to 20 keywords per list, 200 characters each.

Rules

Only active rules are evaluated during ingestion. Disabling a rule is a soft delete.

Notification channels

Per-tenant delivery settings. Every configured channel receives every alert; leaving a channel empty disables it for this tenant. Email also requires the server to hold a Resend API key and sender address, and Telegram requires a bot token — either the per-tenant one below or the deployment-wide fallback.
